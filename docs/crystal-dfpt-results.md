# Crystal DFPT results at 300 K

Actual native Rust calculations for six crystals, with two electronic k meshes
per crystal, passed **all 432 Cartesian Hessian components** against force
differences. The largest Richardson error is **7.573e-10 Hartree/bohr²**.
These are fixed-cell, phonon **q = Gamma** results; the electronic k mesh
is a separate integration setting. No finite-displacement Hessian is used
by the analytic production calculation.

The retained receipt was generated by package version `0.7.0`.
Full analytic, two raw finite-difference and Richardson matrices, structures,
masses, SCC attempts and exact source fingerprints are in
[crystal-dfpt-results.json](../tests/data/crystal-dfpt-results.json).

## Structures and common conditions

Each neutral primitive cell contains two atoms. Cartesian lattice-vector rows
are `(0,a/2,a/2)`, `(a/2,0,a/2)`, `(a/2,a/2,0)` angstrom. Atom A is at
the origin; atom B is at `(a/4,a/4,a/4)` for diamond/zincblende and
`(a/2,0,0)` for rocksalt. These are specified representative inputs, with
**no geometry or cell optimization and no experimental-accuracy claim**.

| C-diamond | diamond | 3.5670 | [6, 6] | [12.011, 12.011] |
| Si-diamond | diamond | 5.4310 | [14, 14] | [28.085, 28.085] |
| SiC-zincblende | zincblende | 4.3600 | [14, 6] | [28.085, 12.011] |
| LiF-rocksalt | rocksalt | 4.0260 | [3, 9] | [6.94, 18.998] |

| MgO-rocksalt | rocksalt | 4.2120 | [12, 8] | [24.305, 15.999] |

Both electronic meshes are explicitly Gamma-centred: `1x1x1` is Gamma-only;
`2x2x2` includes Gamma and the half-reciprocal-coordinate points. Time-reversal
folding is enabled. The full cubic point symmetry is retained. The existing
offset Monkhorst-Pack default is a different quadrature and must not be
substituted when reproducing these numbers.

All calculations use builtin scalar GFN1 parameters and **300 K electronic
temperature**, without SOC or ML corrections. Hessians differentiate the
canonical electronic free energy at fixed cell and electron number.
Energy/charge SCC tolerances are `1e-13` Hartree / `1e-11`, with at most
1000 iterations per attempt. The common convergence policy tries mixing
`0.4`, then `0.1`, then `0.05` only after SCC nonconvergence; temperature and
Hamiltonian stay fixed. The converged setting is reused for displaced forces.
The AO image cutoff is 30 bohr; remaining `PbcOptions::default()` controls
are recorded in every JSON case.

Across all cases, the largest acoustic magnitude is `3.784e-05 cm^-1`,
the largest ASR residual is `4.441e-16 Hartree/bohr²`, and the largest
**raw, pre-symmetrization** Hessian asymmetry is `5.100e-16 Hartree/bohr²`.
No acoustic-sum-rule projection or frequency clipping was applied by the
validation driver. The production Hessian averages its transpose pairs;
the independent force differences are neither symmetrized nor projected.

For each of six nuclear coordinates, independently converged analytic gradients
at `R +/- h` give `H_FD(h) = [g(R+h)-g(R-h)]/(2h)`, with
`h = 0.001` and `0.0005` bohr. Every one of the 36 ordered components
is checked against `[4 H_FD(h/2)-H_FD(h)]/3`, including zeros and
transpose-related entries. Pass limits are `2e-5 Hartree/bohr²` for the
component error and `1e-8 Hartree/bohr²` for both ASR and raw asymmetry.

## Interpretation and scope

The Si `2x2x2` optical instability is present in independently displaced-force
curvatures as well as DFPT. It is a result of this model, specified lattice and
sampling, not evidence of a positive-frequency stable crystal. Differences
between the two coarse electronic meshes are substantial, especially for Si
and MgO; these results do **not** establish Brillouin-zone convergence.
Interpreting physical stability requires cell/geometry relaxation and sampling
convergence. No experimental or higher-level phonon comparison is claimed.

These tests cover scalar Gamma-phonon Hessians for the listed structures.
They do not validate arbitrary-q dispersion, finite-temperature anharmonic
phonon renormalization, SOC Hessians, or nonanalytic LO-TO splitting.
The temperature here is electronic smearing, not a lattice heat bath.

## Reproduce and use the APIs

From the crate root:

```sh
cargo test --profile reltest --test crystal_dfpt_validation -- crystal-raw.json
```

The full Rust driver is
[tests/validation/crystal_dfpt_validation.rs](../tests/validation/crystal_dfpt_validation.rs).
It explicitly calls `pbc_gamma_hessian` or `pbc_kpoint_hessian` with
`KMesh { size, gamma_centered: true, fold_time_reversal: true }`.

Equivalent native and ASE Hessian calls for the carbon `2x2x2` case:

```python
import numpy as np
from ase import Atoms
from ase.units import Hartree, Bohr
from gfn1_rs import Gfn1NativeCalculator, GFN1RSCalculator
a = 3.567
cell = [[0,a/2,a/2],[a/2,0,a/2],[a/2,a/2,0]]
numbers, positions = [6,6], [[0,0,0],[a/4,a/4,a/4]]
controls = dict(electronic_temperature=300., max_scc=1000,
                energy_tolerance=1e-13, charge_tolerance=1e-11)
calc = Gfn1NativeCalculator(**controls)
h = calc.hessian_periodic(numbers, positions, cell, kgrid=(2,2,2), gamma_centered=True)
atoms = Atoms(numbers=numbers, positions=positions, cell=cell, pbc=True)
atoms.calc = GFN1RSCalculator(kgrid=(2,2,2), **controls)
h_ase = atoms.calc.get_hessian(atoms=atoms, gamma_centered=True)
np.testing.assert_allclose(h_ase, np.asarray(h)*Hartree/Bohr**2, atol=1e-9)
```

`gamma_centered=True` is an explicit per-property choice here. It does not
change the ordinary ASE energy/force cache's offset-mesh default. For matching
native force differences call `calculate_periodic(..., gamma_centered=True,
compute_gradient=True)` with the same mesh. Do not compare different quadratures.
The added keyword is optional and leaves existing calls compatible.

General Rust, native Python and ASE response usage:
[soc-dfpt.md](soc-dfpt.md). Existing broader crystal/supercell tests and their
separate conditions are documented in [pbc.md](pbc.md).
